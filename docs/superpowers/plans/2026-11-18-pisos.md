# Pisos — plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ferramenta *Piso* (mestre): pisos de seis materiais pintados por cômodo, retângulo ou pincel, guardados na grade fina como o relevo e desenhados por pixel na placa de vídeo com o visual da página aprovada.

**Architecture:**
- **Shared:** guarda o piso como o relevo, um byte por ponto fino (4 por casa) em pedaços de 8 × 8 casas, com material e sentido. As contas do pincel, do retângulo e do cômodo ficam aí, com teste. O cômodo usa as faces das paredes (`wallRooms`).
- **Servidor:** aplica, valida e envia só os pedaços que mudaram, por evento próprio.
- **Placa de vídeo:** um passo novo do renderizador do chão desenha o piso por cima do terreno e da água e por baixo da camada do relevo. É um programa por material; a borda sai da cobertura interpolada. A camada é guardada e só refeita quando a visão, o piso ou a luz mudam.
- **Sem WebGL 2:** cor chapada no canvas.

**Tech Stack:** TypeScript, WebGL 2, React + react-konva + Mantine, node:test.

**Spec:** [docs/design/pisos.md](../../design/pisos.md). Visual aprovado: `docs/design/pisos-teste.html`.

## Global Constraints

- **Byte do ponto:** material nos 4 bits de baixo (0 sem piso; 1 a 6 = `plank`, `plankWide`, `flagstone`, `tile`, `mosaic`, `carpet`, nessa ordem) e sentido no bit de valor 16 (1 = vertical). Os bits de valor 32, 64 e 128 são reservados (byte com eles é recusado). Ponto sem piso = 0.
- **Pedaços:** os mesmos do terreno (`TERRAIN_CHUNK_SIDE` = 32, `TERRAIN_FINE` = 4); pedaço vazio some; limite `LIMITS.terrainChunks`.
- **Cômodo:** qualquer contorno fechado de paredes, portas e janelas, de qualquer desenho (cerca, paliçada e muralha fecham). Vale a menor face que contém o ponto; lugares fechados inteiros dentro dela ficam de fora; o piso vai até a linha do meio da parede (os pontos sobre o contorno entram).
- **Retângulo:** na interface os cantos encaixam na casa (Shift: meia casa); o servidor aceita qualquer múltiplo de 1/4 de casa.
- **Grid hexagonal:** o piso funciona (padrão na malha quadrada); trocar o grid apaga o piso, e a confirmação da troca cita o piso.
- **Placa de vídeo:**
  - um programa por material (`ProgramCache`);
  - sorteio pelos bits (`floatBitsToUint`);
  - detalhe fino vira média abaixo de ~2 px (`detail()`);
  - luz relativa (`faceLight`);
  - aquarela com `textureLod` quando dentro de condicional;
  - nada de crase dentro das strings de shader (quebra o template).
- **Visual:** o mesmo da página aprovada.
- **Só visual** (ADR-06): todos veem o piso, por baixo da névoa.
- **Regras do projeto:**
  - textos em `pt-BR.ts`, com tradução em `en.ts` e `es.ts`; recusas como modelo em `serverText.ts`;
  - sem `any` nem cast forçado; nomes com significado; comentários em português;
  - campo novo no arquivo de sessão, com ida e volta, e no `save-guard.test.ts`;
  - sem commits do agente: sugestão de commit no fim de cada tarefa, esperando o "segue".

## Review Focus

- **Cômodo com porta aberta ou parede faltando:** sem contorno fechado, o servidor recusa com a mensagem; não pinta o mapa inteiro. Teste na Tarefa 1.
- **Tapete sobre laje:** os dois materiais encostados, sem fresta entre eles; a barra do tapete segue a borda do tapete. Verificação na placa, na Tarefa 4.
- **Desfazer depois de pintar um cômodo grande** (vários pedaços): volta tudo de uma vez. Teste na Tarefa 2 (`floor:restore` com vários pedaços).
- **Trocar de cena e salvar ou carregar a sessão:** o piso vai e volta. Teste na Tarefa 2.
- **Mapa antigo (sem `floors`):** abre igual, sem erro. Teste na Tarefa 2 (arquivo sem o campo).

  export const FLOOR_MATERIALS = ["plank", "plankWide", "flagstone", "tile", "mosaic", "carpet"] as const;

  export type FloorChunks = Record<string, string>;      // como ReliefChunks
  export interface FloorPoint { material: FloorMaterial | null; vertical: boolean }
  export type FloorShape =
    | { kind: "brush"; radius: number; points: number[] }
    | { kind: "rect"; from: { x: number; y: number }; to: { x: number; y: number } }
    | { kind: "room"; at: { x: number; y: number } };
  export interface FloorStroke { material: FloorMaterial | "erase"; vertical: boolean; shape: FloorShape }
  export function encodeFloorPoint(point: FloorPoint): number;
  export function decodeFloorPoint(value: number): FloorPoint;
  export function validFloorByte(value: number): boolean;
  export function floorAt(chunks: FloorChunks, fineX: number, fineY: number): FloorPoint;
  /** Contorno (pontos x, y em casas) do lugar fechado que contém `at` e os lugares fechados de dentro (buracos); null fora. */
  export function floorRoomAt(walls: Wall[], at: { x: number; y: number }, sceneStyle: WallStyle): { outer: number[]; holes: number[][] } | null;
  /** Aplica (muda `chunks`) e devolve as chaves que mudaram; `null` se o cômodo não é fechado. */

- `wallRooms(walls, sceneStyle, options?: { allStyles?: boolean })`: com `allStyles`, não tira as vazadas nem `OPEN_AIR`.

  - Pincel: `hypot < radius`.
  - Retângulo: `min ≤ x ≤ max` nos dois eixos.
  - Cômodo: dentro do contorno de fora, incluindo os pontos sobre ele (tolerância 1e-6), e fora de todos os buracos (os pontos sobre o contorno de um buraco ficam de fora).
- `"erase"` grava 0. O pedaço todo 0 some (`delete`).

### Task 4: Piso na placa de vídeo e reserva no canvas

**Files:**
- Create:
  - `client/src/map/ground/floorShader.ts`: `floorFragment(material: FloorMaterial): string`, portado da página aprovada;
  - `client/src/map/ground/floorPass.ts`: `FloorPass`;
  - `client/src/map/floor/FloorLayer.tsx`: reserva no canvas.
- Modify: `GroundRenderer.ts` (`setFloors`, ordem dos passos), `GroundLayer.tsx` (prop `floors`), `BattleMap.tsx` (passa o piso ao chão, ou usa a reserva sem `groundLit`)

**Interfaces:**
- Consumes: `FloorChunks`, `FLOOR_MATERIALS` e `decodeFloorPoint` (Task 1); `useApp.floors` e `floorPreview` (Task 3).
- Produces:
  - `GroundRenderer.setFloors(chunks: FloorChunks): void`;
  - `FloorPass { setChunks(chunks): void; draw(view, width, height, scene): void; get pending(): boolean; dispose(): void }`;
  - `FLOOR_FLAT_COLOR: Record<FloorMaterial, string>` (exportado de `floorShader.ts`, usado pela reserva e pelo painel).
- **Dados na placa:** os bytes vão numa textura `R8UI` cobrindo a caixa dos pedaços com piso, com uma borda de um texel vazio (como os pesos do terreno), lida com `texelFetch`.
- **Cobertura:**
  - "tem piso" é a interpolação bilinear dos 4 pontos vizinhos (1 se o byte ≠ 0), cortada em 1/2, com borda anti-serrilhada de 1 px;
  - o material do pixel é o que tem a maior interpolação entre os 4 vizinhos;
  - entre materiais a cobertura é cheia, e a troca acontece onde as interpolações se cruzam, numa linha lisa.
- **Perto da borda:** a distância até a borda é estimada por 8 amostras em anel, nos raios 0,25, 0,6 e 1,2 casa. Ela serve para:
  - a sujeira e o desgaste (borda do piso inteiro);
  - a barra do tapete (borda do material tapete).
- **Desenho:**
  - um programa por material, com o padrão da página (sentido pelo bit do ponto) e a luz relativa de `faceLight`;
  - a camada fica numa textura do tamanho da tela, refeita só quando a visão, os pedaços ou a luz mudam;
  - no `render`, o piso vai depois da água e antes da camada do relevo.
- **Reserva (`FloorLayer`):** sem `groundLit`, desenha no canvas cada ponto com piso como um quadradinho de 1/4 de casa na cor chapada do material, pedaço a pedaço em cache. Fica na camada do terreno de reserva, por cima dele.
