# Baús com loot: plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** baús no mapa com loot que os jogadores abrem juntos, escolhem durante uma contagem e disputam com d20 automático; armas viram itens que se empunham.

**Architecture:** objeto novo da cena (`battle.chests`), no padrão das tochas fixas: ação em `ActionPayloads` → handler em `server/src/actions/chests.ts` → filtro em `server/src/view.ts` → arquivo de sessão. A disputa (contagem, interesses, d20) roda no servidor; a regra de divisão fica numa função pura (`server/src/loot.ts`) testada com d20 injetado. O relógio da contagem usa um `store.schedule` que o `app.ts` liga ao `broadcast()`.

**Tech Stack:** TypeScript, Express + Socket.IO (servidor autoritativo), React 19 + Mantine + react-konva + Zustand, testes `node:test` + socket.io-client (`server/test/helpers.ts`).

**Spec:** [docs/design/baus.md](../../design/baus.md)

## Global Constraints

- Textos de interface, recusas e comentários em português; recusas como modelo (`fail("… {name}.", { name })`) com tradução em `client/src/i18n/serverText.ts`; chaves novas nos três catálogos (`pt-BR`, `en`, `es`).
- Permissões só no servidor; jogador nunca recebe baú invisível, baú coberto pela névoa nem o loot antes da primeira abertura (filtro em `view.ts`, com teste).
- Campo novo no jogo vai no arquivo de sessão (ida e volta) e no `save-guard.test.ts` com `Required<…>`.
- O app registra, não aplica regra (ADR-06): armadura não muda CA; o d20 é sorteio de loot.
- Interface só com Mantine e o tema (`client/src/theme.ts`), identidade do guia visual; peça visual nova (desenho do baú, janela de loot) só depois do protótipo aprovado pelo dono.
- Janela de loot cabe em 375 px (MobileShell).
- Antes de dizer que terminou: `npm run typecheck` e `npm test` passando. O dono faz os commits: no fim de cada tarefa, entregar os comandos (`git add -A` e `git commit -m "…" -m "Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>"`), cada um no seu bloco.
- Toda mudança percebida: linha em `## [Não lançado]` do CHANGELOG; mudança de uso: README; item do backlog marcado.

## Review Focus

- Dois jogadores clicam *Pegar* no mesmo item ao mesmo tempo: o servidor processa um de cada vez; o segundo recebe "Esse item já foi levado." (teste na Tarefa 4).
- O mestre apaga ou edita o baú durante a contagem: a disputa daquele baú acaba sem entregar nada (teste na Tarefa 4).
- Jogador sem personagem quer um item: recusado com "Crie seu personagem antes." (teste na Tarefa 4).
- Ficha cheia (`LIMITS.items`): a entrega daquele item para aquela pessoa é recusada com aviso no log, e o item fica no baú (teste na Tarefa 4).
- Baú aberto por um jogador enquanto outro baú está em contagem: só uma disputa por vez; a segunda abertura é recusada com "Espere a escolha do outro baú acabar." (teste na Tarefa 4).
